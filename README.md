# Переговорка — бронирование переговорной

Тестовое задание Frontend Engineer: интерфейс бронирования переговорной на рабочий день (09:00–18:00).

**Стек:** Next.js 16 (App Router) · React 19 · TypeScript (strict) · TanStack Query · React Hook Form + Zod ·
Tailwind CSS v4 · Radix · Vitest + Testing Library · Biome. Архитектура — **Feature-Sliced Design**, как в daily-mail.

## Запуск

```bash
pnpm install
pnpm dev            # http://localhost:3000
```

```bash
pnpm verify         # type-check + biome + проверка FSD-импортов + тесты
pnpm test           # 47 тестов
pnpm lint:arch      # только правила слоёв
pnpm build && pnpm start
```

Переменные окружения — в `.env.example` (всё опционально).

## Что сделано

- Выбор даты (стрелки, пикер, «Сегодня»). Дата в URL — ссылкой можно поделиться, «Назад» работает.
- Таймлайн дня: клик по свободному слоту — создание, клик по брони — редактирование. Есть линия «сейчас»,
  прошедшее время заштриховано.
- Создание, редактирование, удаление (с подтверждением).
- Все 8 бизнес-правил — одна чистая функция, общая для формы и сервера (`entities/booking/model/rules.ts`).
- В селектах времени недоступные варианты (прошлое/занято) видны, но выключены. При смене начала окончание
  подстраивается само.
- **409**: понятное сообщение с указанием, кто занял время; расписание обновляется до показа ошибки;
  введённые данные остаются в форме; поле подсвечивает конфликт.
  Воспроизвести: чекбокс **«Демо: коллега успевает раньше»** → сохранить любую бронь.
- Также обрабатываются 422 (по полям), 404 (бронь удалили — «создать новую с этими данными»),
  начавшаяся бронь (только просмотр), отсутствие сети.
- Состояния: загрузка (скелетон), пустой день, ошибка с «Повторить», фоновое обновление, отправка формы.
- Адаптив (одна колонка на телефоне) и доступность: настоящие кнопки с подписями для скринридера, `aria-invalid`/
  `aria-describedby`, live-регионы, перевод фокуса на панель, видимый фокус, контраст AA, reduced motion.
- Mock API (`/api/bookings`) по контракту из ТЗ, на Route Handlers + in-memory репозитории за интерфейсом.

Подробный реестр с привязкой к коду и тестам — **[docs/FEATURES.md](docs/FEATURES.md)**.
Архитектура — **[ARCHITECTURE.md](ARCHITECTURE.md)**, решения — `docs/adr/`.

## Структура

```
src/
├─ app/                 # Next routing + api/bookings (тонкие route handlers)
├─ app-layer/           # providers, токены дизайна, шрифты
├─ pages-layer/booking  # композиция экрана
├─ widgets/             # day-schedule, booking-panel
├─ features/            # select-date, save-booking, delete-booking, simulate-race
├─ entities/booking     # model (домен) · api (сеть, DTO, ошибки) · lib · ui
├─ shared/              # api · config · lib · hooks · ui
└─ server/bookings      # mock-бэкенд: service → repository
```
